# MRC V0.0.14 — CLI Experience Authority

**Owner approval source:** live Main-PC v0.0.13 acceptance, 2026-09-09/10 Pacific  
**Branch:** `precert-v0.0.14`  
**Baseline:** published v0.0.13 prerelease commit `22092f22c0f9d1b5f8196ee87512e8b5254b0927`  
**Final target remains:** `v0.1.0`

## 1. Purpose
V0.0.14 improves the terminal-command experience discovered during live Main-PC v0.0.13 acceptance without weakening any v0.0.13 runtime, ownership, control, updater, Doctor, Diagnose, GUI, animation, or release-safety authority.

V0.0.13 remains immutable evidence. Do not silently replace or mutate its published package.

## 2. T01 — Bare `MRC` Launch Experience
The bare `MRC` command is a first-class terminal command and SHALL use the central semantic CLI presentation/renderer pipeline.

The v0.0.13 direct `TextWriter.WriteLineAsync` launch output is superseded.

Requirements:
- multi-line MRC-branded launch result, not a single generic sentence;
- semantic segmented colors in interactive PowerShell/Terminal;
- deterministic plain text when redirected;
- cyan product/command heading;
- white field labels;
- green success/result token for successful launch/activation;
- metadata/secondary detail uses the existing semantic palette;
- distinguish `OPENED` from `ALREADY RUNNING` / restored-and-focused behavior truthfully;
- failed launch remains a non-zero exit and uses the central error renderer;
- no fake progress bar or fabricated launch stages;
- no command-specific `Console.ForegroundColor` calls.

The output should feel like an MRC control-console event while remaining concise.

## 3. T02 — Help as a Real Terminal Table
`MRC --help` SHALL render as a scan-friendly terminal command-reference table rather than command rows followed by alias footnotes.

Requirements:
- one command record per logical row;
- explicit `COMMAND`, `ALIASES`, and `DESCRIPTION` column headers;
- canonical command in cyan;
- aliases in gray/secondary tone;
- description in white;
- stable column alignment;
- long descriptions wrap only within the DESCRIPTION column and continuation lines align under DESCRIPTION;
- preserve every supported alias;
- redirected output remains deterministic plain text;
- ordinary terminal widths remain readable without orphaned command/description lines;
- no box-heavy generic spreadsheet/card styling; preserve MRC terminal aesthetic;
- central reusable table/column formatting rather than ad hoc spaces per command.

## 4. T03 — Update Progress Bar
`MRC --update` SHALL add a truthful terminal progress bar driven only by existing `UpdateProgress.Percent` authority.

Requirements:
- no fake time-based or animated percentage;
- central reusable progress-bar formatter;
- bounded width safe for ordinary terminals;
- semantic stage/result coloring preserved;
- redirected output deterministic plain text with no ANSI/control garbage;
- 100% only when updater reports 100%;
- progress-bar presentation must not alter updater execution, verification, activation, rollback, or release selection behavior.

## 5. Safety Boundary
All v0.0.13 hard safety laws remain unchanged, including:
- exact machine/root authority;
- managed/external/unattributed ownership separation;
- no control of external/system runners;
- BUSY protection and force confirmation;
- verified graceful stop lifecycle and restart safety;
- Doctor repair risk boundaries;
- Diagnose read-only behavior;
- SHA-256 / manifest / atomic activation / rollback updater protections;
- single-instance GUI behavior;
- 20 FPS shared animation architecture;
- GUI visual/readability acceptance.

## 6. TDD / Acceptance
Each T01–T03 item follows RED → correct-failure proof → minimal GREEN → complete regression.

V0.0.14 is not accepted until live Main-PC terminal evidence confirms all three experiences and all inherited v0.0.13 runtime/control/release gates remain GREEN.

Global certification rule remains unchanged: every applicable category must be exactly 10.0/10 or certification remains HOLD.
