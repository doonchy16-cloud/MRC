# MRC v0.0.15 Reference Replica Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build MRC v0.0.15 as a native-WPF 1:1 visual reconstruction of the Owner-authored Runner Control reference while preserving verified MRC runtime, lifecycle, ownership, updater, diagnostics, and safety behavior.

**Architecture:** `MRC.Core` remains untouched except for existing version authority consumption. The GUI is decomposed into focused WPF controls and one reference theme dictionary. `MainWindow` composes those controls, owns drawer visibility/focus, and remains the bridge into the existing `RunnerOperationsService`. The CLI change is limited to Help token coloring. Visual acceptance requires exact-head rendered evidence and human comparison to the Owner reference.

**Tech Stack:** .NET 10, WPF/XAML, C#, PowerShell, GitHub Actions, existing MRC test harnesses.

**Spec:** `docs/superpowers/specs/2026-09-10-mrc-reference-replica-design.md`

## Global Constraints

- Implementation version is exactly `0.0.15`; final product target remains `0.1.0`.
- Create branch `precert-v0.0.15` from the commit containing this final plan. Do not implement on `precert-v0.0.14`.
- Published/installed `v0.0.14` is frozen historical/live evidence and must not be rewritten.
- The Owner-authored 2048x1222 Runner Control screenshot is the primary visual authority for v0.0.15 wherever safety/runtime truth does not conflict.
- Native WPF only. No WebView2, browser shell, Direct2D rewrite, or external UI framework.
- Exact machine authority stays `DOONCHYSCOMPUTI`; runner root stays `D:\Git_Runners_Main`.
- MANAGED / EXTERNAL / UNATTRIBUTED ownership laws remain unchanged. External/unattributed runtimes never gain lifecycle controls.
- `RunnerOperationsService` remains the GUI lifecycle boundary. New visual controls never invoke process primitives or `RunnerEngine` lifecycle methods directly.
- BUSY protection and explicit FORCE STOP confirmation remain mandatory.
- TURN ALL OFF continues to skip BUSY runners and never force-stops them.
- Exactly one shared 20 FPS animation timer remains. No control creates its own timer.
- Primary card rail has exactly three lifecycle slots. DETAILS is a separate 28x28 header affordance.
- Canonical responsive outcomes: 2048x1222 → 4 columns; 1200x760 → 2; 1180x760 → 2; 900x560 → 1.
- Reference geometry target at 2048: ~41 px field inset, ~469 px card width, ~150 px card height, ~22 px gaps, ~19 px horizontal card padding, ~46 px action height, ~3.1:1 card aspect.
- Control Drawer width is `min(400 px, window width - 32 px)` and overlays rather than resizing the runner grid.
- System Drawer overlays upward and never uses more than 35% of available window height.
- Help remains `COMMAND | ALIASES | DESCRIPTION`; interactive `MRC` token = yellow, option token = cyan, aliases = gray, description = white; redirected output remains plain text.
- Every implementation slice uses RED → prove intended failure → minimal GREEN → focused verification → commit.
- No visual PASS from structural tests alone. Fresh renders and human review are mandatory.
- Every applicable certification category must individually score 10.0/10. Any lower score or unverified requirement = HOLD.

```csharp
namespace MRC.Gui.Presentation;

public static class ReferenceReplicaMetrics
{
    public const double CanonicalWidth = 2048;
    public const double CanonicalHeight = 1222;
    public const double LargeFieldInset = 41;
    public const double CardTargetWidth = 469;
    public const double CardTargetHeight = 150;
    public const double CardGap = 22;
    public const double CardHorizontalPadding = 19;
    public const double ActionHeight = 46;
    public const double MinimumCardSlotWidth = 470;
    private const double WindowChromeAllowance = 48;

    public static int ColumnCountForWidth(double windowWidth)
    {
        if (double.IsNaN(windowWidth) || double.IsInfinity(windowWidth) || windowWidth <= 0) return 1;
        var usable = Math.Max(0, windowWidth - WindowChromeAllowance);
        return Math.Clamp((int)Math.Floor(usable / MinimumCardSlotWidth), 1, 4);
    }
}
```

```csharp
private async void RunnerControlCard_OnActionRequested(
    object? sender,
    RunnerCardActionRequestedEventArgs e)
{
    if (_previewMode || _operations is null || _operationInProgress) return;

    switch (e.Action)
    {
        case RunnerCardAction.Start when e.Row.CanStart:
            await ExecuteCardOperationAsync(e.Row, "START", () => _operations.Start(e.Row.Runner));
            break;
        case RunnerCardAction.Stop when e.Row.CanStop:
            await ExecuteCardOperationAsync(e.Row, "STOP", () => _operations.StopIdle(e.Row.Runner));
            break;
        case RunnerCardAction.Restart when e.Row.CanRestart:
            await ExecuteCardOperationAsync(e.Row, "RESTART", () => _operations.Restart(e.Row.Runner));
            break;
        case RunnerCardAction.ForceStop when e.Row.State == RunnerState.BUSY:
            await ExecuteForceStopAsync(e.Row);
            break;
        case RunnerCardAction.Details:
            new DiagnosticDialog(e.Row) { Owner = this }.ShowDialog();
            break;
    }
}
```
