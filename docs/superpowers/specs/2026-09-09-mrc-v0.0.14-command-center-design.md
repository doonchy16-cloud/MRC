# MRC v0.0.14 Command Center Design

## Goal
Build v0.0.14 as a native Windows command center whose controls are trustworthy first and visually excellent second, while preserving v0.0.13 as immutable evidence.

## Architecture
MRC remains WPF/.NET. The runtime/control core owns all START, STOP, RESTART, ALL ON, ALL OFF, BUSY protection, ownership proof, and state reconciliation. The GUI is a client of that core and never implements runner lifecycle logic itself.

The GUI moves from a full-screen terminal table to a responsive card-based control center. Terminal styling remains selectively in CLI, diagnostics, paths, PIDs, sessions, build metadata, and event-style detail.

## P0 Control Reliability
The live v0.0.13 screenshot showed an inaccessible Session-0 Runner.Listener as UNATTRIBUTED. Current START preflight blocks when genuinely unattributed runner-process ownership exists. The repair must improve ownership evidence rather than disable the safety check.

Use a Windows process-enumeration parent-PID fallback that does not require opening the protected process. This allows ancestry correlation from an inaccessible Runner.Listener to a running external actions.runner.* service when the evidence proves that relationship. Proven external services remain non-controllable and do not block unrelated managed START. Truly unattributed processes still fail closed.

Add a first-class Restart operation. Restart is IDLE -> verified graceful STOP -> verified OFF -> START -> STARTING. It never means kill + delay + start. BUSY restart remains protected.

## Native Command Center GUI
The supplied Runner Control screenshot is a reference for hierarchy and separation, not a visual copy.

Use a modern dark native application shell with:
- strong MRC header, authorization, machine/root, and version metadata;
- clear summary metrics;
- search/filter/bulk-action toolbar;
- responsive runner cards;
- visible state badge/indicator;
- runner and repository identity;
- START / STOP / RESTART buttons whose enabled state exactly matches core authority;
- diagnostics/details affordance for BUSY/ERROR where appropriate;
- separate system-findings surface;
- selective monospace styling for technical metadata.

Responsive targets: approximately 3 generous columns at 2048x1222, 2 around 1200x760, and a readable minimum layout at 900x560 with scrolling where needed.

## CLI Experience
Bare MRC uses central semantic presentation; Help becomes a COMMAND / ALIASES / DESCRIPTION table; Update gains a truthful percent-driven progress bar. Redirected output remains deterministic plain text.

## Safety
No external/system runner controls. Exact machine/root boundary remains. BUSY force stop still requires explicit confirmation. Graceful stop and verified exit remain mandatory. Doctor/Diagnose/updater safety is unchanged.

## Acceptance
Every behavioral change is RED -> verified correct failure -> GREEN -> full regression. Generate and inspect fresh GUI previews at 2048x1222, 1200x760, 1180x760, and 900x560. Final live Main-PC acceptance repeats START/STOP/RESTART and bulk operations and proves no duplicate-session conflict. Every applicable certification category must be exactly 10.0/10.
